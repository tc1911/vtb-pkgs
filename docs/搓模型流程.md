# 从一张图到能驱动的 Vtuber 模型（本机全自动流程）

整条链已在 ds 样例上端到端验证过：拆层 20/20 语义标签、moc3 正常渲染、面捕驱动、虚拟摄像头输出。
① 和 ②③④ 可以并行，②③④ 必须按顺序。

## ① 出图
- 本机 ComfyUI + AnimagineXL 4.0，入口 http://127.0.0.1:8188（`~/opt/comfyui.sh start`）
- 命令行出图：`~/opt/gen_character.py`，提示词规矩见 `~/opt/出图提示词.md`
- **硬要求**（不遵守②就拆不干净）：纯白背景 / 平涂禁渐变 / 单视角单角色 / 别画两套肢体

## ② 拆层
```bash
bash ~/opt/split_run.sh 立绘.png 输出.psd
```
- 内部：See-through（LayerDiff3D 出层 + Marigold 出深度）→ 29 个标准语义层 → 拼成分层 PSD
- 耗时：1024² 约 6 分钟（开 group_offload 省显存，代价慢 2–3×）
- 判据：29 层且层名是标准名（`front hair`、`handwear-l`、`irides-r`、`eyelash-l`…）

## ③ 绑定出 moc3
```bash
bash ~/opt/psd2live-run.sh 输出.psd 模型名
```
- 产出 `~/Live2D/模型名/`：.moc3（运行时）、.cmo3（可回 Live2D 编辑器继续调）、.model3.json、idle/blink/nod/shake 动作、physics3.json、4096 贴图
- 它顺带跑 `~/opt/gen_vtube.py` 生成 `.vtube.json`（参数绑定表），自检不过会当场报出来
- ⚠️ **第二个参数是模型名，不是输出目录**

## ④ 加载
```bash
OPENVT_MODEL=$HOME/Live2D/模型名/模型名.model3.json ~/.local/bin/openvt
```
- 不给 OPENVT_MODEL 就用界面里记住的模型；两者不会叠加（叠加那个 bug 已修）

## ⑤ 驱动
- 面捕常驻：`systemctl --user status openseeface.service`
- 虚拟摄像头：OBS / 浏览器 / ffmpeg 里选 `OpenVT Virtual Camera`（/dev/video10）

## 出问题先看这三处
1. **`~/opt/PATCHES.md`** —— 所有本地补丁 + 已知坑（`DEVICE_LOST` 其实是显存不足；seed 在 XPU 上不生效；`exclusive_caps` 必须 0；等等）
2. `~/opt/compare_split.py 拆层.psd 标准答案.psd` —— 拆层质量对数（语义标签命中率）
3. `/tmp/comfyui_run.log` + OpenVT 的 `--log-file` 输出 —— 原始报错

## 已测基准（ds 样例，用来判断"这次是不是坏了"）
| 项目 | 正常值 |

## 坑：拆层 0 层 = Intel NEO 内核缓存被污染（2026-09-17 真因定稿）
- 症状：层数 0、PSD 只有 4MB、日志 `vae.py` 报 `invalid value encountered in cast`、`PostProcess complete: 0 layers`；继续折腾还会升级成 `UR_RESULT_ERROR_OUT_OF_RESOURCES` / `UR_RESULT_ERROR_DEVICE_LOST`。
- **真因：`~/.cache/neo_compiler_cache`（Level Zero/IGC 计算内核缓存）里存在坏内核 → 复用坏内核算出 NaN → alpha 全 0 → 图层全被判定为空。**
  与种子、dtype、`group_offload` **都无关**。铁证：缓存被污染时把分辨率降到 512²（显存宽裕、关 offload）依旧必 0 层；`rm -rf ~/.cache/neo_compiler_cache` 后**同一配置立刻出 29 层**。
- ✅ 正确做法：`rm -rf ~/.cache/neo_compiler_cache && ~/opt/comfyui.sh restart`（缓存可重建，不是数据；重编译会慢一点）。`split_run.sh` 的失败重试已改为自动执行这一步。
- ❌ 已试过且无效/有害，勿重犯：
  1. 换种子——与 NaN 无关，白烧 3×6 分钟
  2. `--fp32-vae`（ComfyUI 开关）——管不到节点自己的 diffusers 管线，无效
  3. 节点 VAE/trans_vae 强转 fp32（nodes.py:383/385/467）——无效，且多占显存诱发 DEVICE_LOST
  4. dtype bf16→fp16（nodes.py:345/449）——无效，已回滚为 bf16
- `group_offload` 取 node 默认 **False**（03:18 成功那次就是 False；开启它反而会在显存不够时把错误伪装成 NaN/DEVICE_LOST）。
- 唯一必要的补丁：`enable_group_offload(mm.get_torch_device(), ...)`（硬编码 `'cuda'` → 设备无关），不用 offload 也留着无妨。
- 出现 DEVICE_LOST / OOM 的处置次序：① 清内核缓存 + 重启 ComfyUI → ② 关掉占显存的程序（浏览器/QQ/missioncenter 等）→ ③ 重启机器（XPU 驱动状态劣化只有重启能恢复）。
- 回滚 nodes.py：`cd ~/opt/ComfyUI/custom_nodes/ComfyUI-See-through && cp nodes.py.bak-0352 nodes.py && ~/opt/comfyui.sh restart`

## 拆层产物的两类污染（2026-09-17 定位）
See-through 在本机条件下会把「背景 / 地面阴影」当成某个部位标签预测出来，表现为两类污染，
都由 `~/opt/png2psd.py` 自动清理（加 `--keep-all` 可关闭）：

1. **整块灰板** —— 白底图里被命名成 `neckwear`，实测画布覆盖率 44.3% / 纵向占满 97.5% / 平均饱和度 3.0。
   不丢它，虚拟摄像头画面里就一直挂着一整块灰板。判定用三重条件（覆盖率 > 35% 且纵向 > 95% 且饱和度 < 10）后整层丢弃；
   合法的 `back hair` 只有覆盖率 13.3% / 纵向 83%，不会误伤（只卡饱和度会误杀 topwear 8.5、tail 4.1）。
2. **半透明白雾** —— `topwear` 8 万可见像素里有 6.4 万是 α<128 的近白色 (232,225,223)，
   即白底 + 地面阴影被半透明地糊进了衣服层，渲染成角色周围一片白蒙蒙。
   清理规则：**低 alpha（≤128）且近白（最小通道 > 180）的像素直接清零**，共清掉 64148 像素；
   头发的深色软边（back hair 软像素 RGB 135）不受影响。

顺带把「几何被拉伸」这桩悬案结掉：按 layers.json 的 `left/top` 换算，脸 227-286、前发 214-303、耳 218-256
全部落在预期的角色框 (177,25,340,492) 之内 —— **PSD 几何本来就是对的**，
之前量出的「横向拉伸 1.48×」是鬼影把包围盒撑大造成的假象（排除鬼影后剩下 0.86×~1.08×）。

## 层序：See-through 给的顺序对某些角色是错的（2026-09-17 白狐实测）

节点的 20 个 tag 是按固定的「背→前」写死的，但有两个位置在常见角色上会翻车：

| 症状 | 原因 | 修法 |
|---|---|---|
| 尾巴像一条白香肠盖在裤子上，裤腿缺一块、里面还有残留的深灰楔子 | `tail` 排在 `legwear`/`footwear` **之后**（等于画在裤子前面）。原画里尾巴是从胯部往左下扫、到脚踝再从腿后面钻出来的，裤子压着它 | 把 `tail` 挪到 `legwear` 之前（紧随 `back hair`） |
| 加了 `face` 层后刘海被脸糊住 | `front hair` 排在第 0 位（最底层） | 把 `front hair` 挪到 `face` 之后、眼睛各层之前（原画里刘海盖额头、眼睛眉毛又画在刘海之上） |

**推荐的标准层序（背→前）**，改 `layers.json` 里 `layers` 数组的顺序即可（`png2psd.py` 就按这个数组的顺序叠）：
```
back hair, tail, legwear, footwear, neck, topwear, face,
ears-r, ears-l, front hair,
eyewhite-r/l, irides-r/l, eyelash-r/l, eyebrow-r/l,
nose, mouth, handwear-r/l
```
（`neck` 在 `topwear` 前 = 兜帽领子压在脖子上；`topwear` 在 `legwear` 前 = 卫衣下摆压住裤腰。）

## 语义层缺失时怎么办

拆层是带随机性的：同一条命令、同一张图，两次跑出来的 tag 集合可能不同。白狐实测：
- 21 层那版**没有 `face`** → psd2live 只好用头部包围盒估一个**矩形**当脸，渲染出来就是一块没有轮廓、垂直硬边的白板，下缘横切在兜帽上。
- 24 层那版有 `face`（59×67 px，形状正确）但有白雾/鬼影。

**修法**：把有 `face` 的那次跑出来的 `face_*.png` 拿过来，插进 `layers.json` 的 `layers` 数组（位置：`face` 在 `topwear` 之后、`nose` 之前；`left`/`top` 用它自己 json 里的值，两次跑同一张图坐标空间一致，可以直接搬）。文件名换成新名字、和其余 PNG 放同一目录即可。

**注意** `psd2live` 生成的模型**基底名取自 PSD 文件名**，不是你传给脚本的名字 —— 所以 PSD 一定要按模型名命名（`shiro-v2.psd` → `shiro-v2.*`），否则 `frame.sh` 会找不到 `model3.json`。

## 「某个部位焊死不动」= 它的像素被烤进了别的图层

**症状**：面捕驱动时，尾巴（或头发、袖子）有一份留在原位不动，另一份跟着动 —— 看起来像"有两个图层，其中一个焊死了"。

**成因**：See-through 的分割掩码会串味。白狐那次，整条尾巴（10627 px）**和鞋子的白色**都被烤进了 `back hair` 层。因为 back hair 排在尾巴**后面**、绑在头部那套骨架上，静止时两份完全重合，看不出来；尾巴一动，原点就剩下烤进去的那一份。

**检测**：`~/opt/find_baked.py <layers.json>`
它对每一对「靠后的层 B / 靠前的层 A」，统计 B 有多少不透明像素落在 A 的遮罩里，并给出**顶行差**（B 自身内容顶行 vs 重叠区顶行）。
- 顶行差 = 0~30px：正常遮挡（尾巴被裤子挡、脸被刘海挡、卫衣被手挡）
- 顶行差 > 80px：**串味**，B 里烤进了别部位的内容
- 别看中位数判据：烤进来的那块可能占该层 30%，足以把中位数拖偏（实测漏报）

**修法**（两种，按情况选）：
1. 已知是哪个部位串的 → 用那个部位自己图层的遮罩（**向外膨胀 2px**，否则尾巴一动会留白边）从污染层里抠掉。
2. 位置有硬性约束的层（如 `back hair` 只可能存在于头部）→ 直接横切：白狐那次用「`back hair` 里 y > 150 的像素全部清零」，22710 → 6443 px，剩下的 bbox 精确落在头发区域（x259-293 / y58-98）。

**验证**：psd2live 自检会打印每个 ArtMesh 的 Bounds。修好后 `ArtMeshBackHair` 应当只剩头部那一小块，而不再在脚踝处settle出一个 29×18 的碎片。
